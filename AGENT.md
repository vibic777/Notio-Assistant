# AGENT.md — Notio (монорепозиторий Android + Windows)

Этот файл читается первым. Он собирает правила, которые действуют во всём репозитории, и показывает, где лежат подробные
правила и журналы решений каждой платформы. Если правило платформы и этот файл расходятся, спросить владельца.

## 0. Этот репозиторий — Notio-Assistant

`V:\Projects\Notio-Assistant` — **основной проект Notio** (полная история Git) с 2026-10-14: Notio развивается здесь,
на Android, Windows и Linux, вместе с возможностями ИИ — помощник на локальной модели, MCP, бот (владелец, 2026-10-14:
«в Notio-Assistant это уже основной проект, в dist сборка как была»; Windows D154). Все правила ниже действуют.

- Рабочая ветка — `main`; в неё влита вся ветка `assistant` (Windows D145–D153, `docs/ASSISTANT_PLAN_RU.md`).
- Версии — обычная линия `version.properties` (первая здесь: Android 0.9.112, Windows и Linux 0.9.60); поставка — как
  прежде, правило 6 (`tools/publish_delivery.sh`). Установщик Windows ставится поверх Notio как обновление.
  Тестовые сборки `0.9.N-assistant.K` (Windows D152, D153) возможны только при строке `assistant.build` в
  `version.properties`; без неё всё собирается как обычный Notio. Прежние тестовые сборки — `dist/assistant/`.
- `V:\Projects\Notio` — основной Notio без ИИ, удалённый репозиторий `notio` (владелец, 2026-10-14: «переключаемся
  на основной Notio»). Ошибки Notio исправляются там, в его `main`, и переносятся сюда: `git fetch notio`, затем
  `git merge notio/main` (первое такое — Windows D155). Номера решений D145–D154 Windows заняты этой линией; в
  `V:\Projects\Notio` новые решения берут номера после них. Номера версий двух линий могут совпасть — какую версию
  ставить, решает владелец.
- `private/` (ключ подписи) и `local.properties` скопированы из Notio; ключ тот же (правило 6).

## 2. Правила, действующие всегда

1. **Единственный автор и контрибьютор — vibic777.** Git-автор и коммиттер каждого коммита: `vibic777 <vibic@yandex.ru>`
   (локальная настройка репозитория; глобальную конфигурацию Git не менять). Никаких `Co-Authored-By` и других упоминаний
   ИИ в коммитах, тегах, описаниях релизов и PR. **vibic777 — только контрибьютор репозитория.** Приложение называется
   «Notio by vibic», подпись в нём — «Разработчик: vibic» (Android D228, D299).
2. **Надёжно и стабильно, быстро, экономно.** Каждый код проверяется на: отсутствие падений, бесконечных циклов и работы
   в потоке интерфейса; ничего не опрашивает и не бодрствует без нужды (Android: никакой фоновой работы, кроме будильников
   напоминаний, записи по просьбе человека и службы «Всегда готов к синхронизации», когда человек сам включил её
   переключатель — Android D342, владелец, 2026-10-09; приложение обязано работать в режиме ограничения батареи); никакой тяжёлой
   работы на кадр, ограниченные картинки, закрытые потоки (Android правило 18, Windows «reliable, fast, not greedy»).
   **Работа в фоне и батарея — по списку `docs/BATTERY_RU.md`** (владелец, 2026-10-10; Android D353): 14 правил из
   руководств Android с тем, как каждое сделано в Notio. Новый код, который работает в фоне, ставит будильник,
   держит службу, сеть или экран, сверяется с этим списком до реализации.
3. **Сначала решение, потом код.** Неясность — один вопрос с рекомендуемым вариантом. Решение записывается в журнал
   решений платформы до реализации; документы обновляются тем же шагом, что и код.
4. **Паритет функций.** Новая функция для пользователя на одной платформе тем же шагом записывается в таблицу второй
   (`windows/AGENT.md` §5 / `android/docs/AGENT_EN.md` §2.2) как `PLANNED`.
5. **Коммит после каждой законченной значимой части** (решение построено, проверено, записано). Ничего не отправлять
   (`push`), пока владелец не попросит.
6. **Каждая версия собирается во всех формах поставки**: Android debug и release APK, Windows MSI, EXE и portable ZIP.
   **Каждая поставка лежит в своей папке** `dist/Notio-android-<версия>-windows-<версия>-<дата>/` вместе с `manifest.json`
   (версии, ревизия Git, размер и SHA-256 каждого файла) — как в FitEasy (владелец, 2026-10-08). Раскладывает и подписывает
   release APK `tools/publish_delivery.sh`; прямо в `dist/` файлы не оставлять.
   **Оба APK подписываются только ключом проекта `private/signing/debug.keystore`** (владелец, 2026-10-10; Android D344):
   сертификат SHA-256 `e146abb83b22728ed8ab345d0d8443902505c539dd93b2ed52219d9d73b0f979`. Отладочным ключом машины
   (`<домашняя папка>/.android/debug.keystore`) и любым другим ключом поставку не подписывать и новый ключ не создавать;
   нет файла ключа — поставку не делать и спросить владельца. Перед выдачей проверить сертификат обоих APK
   (`apksigner verify --print-certs`); порядок — `private/signing/SIGNING_RU.md`.
7. **Чистота.** Секреты, ключи, `local.properties`, `keystore.properties`, `private/` и собранные пакеты не попадают в Git.
   После сборки убрать временные файлы (`android/tools/clean_after_build.sh`, `windows/tools/clean_after_build.sh`); тесты
   пишут временное только в `build/`.
8. **Совместимость данных.** Идентификатор приложения, схемы баз, формат резервной копии и протокол синхронизации
   менять только с версией, миграцией и проверкой обеих платформ.
9. **Значки и подсказки.** Кнопка с надписью рисуется значком по смыслу, а надпись всплывает подсказкой: на Android — при
   удержании пальца, на Windows — когда курсор стоит на значке (и при удержании пальца на сенсорном экране). Новая кнопка
   берёт `TextButton` / `OutlinedButton` / `Button` / `IconButton` приложения (Android: пакет `core/ui/tip`; Windows: свой
   пакет) и получает значок и подсказку сама; новое значение — одна строка в `shared/src/com/notio/common/ButtonIcons.kt`.
   Словами остаются кнопки, показывающие значение, имена, чипы, вкладки и переключатели (Android D307, Windows D85).
   **Пункт выпадающего меню** сохраняет слова и получает значок по смыслу рядом с ними: меню берётся из того же пакета
   (`DropdownMenu` / `DropdownMenuItem`), значок подбирается тем же правилом; меню-список значений остаётся без значков
   (Android D314, Windows D93).
10. **Облачные сервисы на паузе** (Android правило 14), пока владелец её не снимет.
11. **Подсказки и справка ведутся вместе с кодом** (владелец, 2026-10-10; механика — Android D332, Windows D113). Каждая
    новая или изменённая функция для пользователя тем же шагом, на обеих платформах и на всех десяти языках, получает:
    **подсказку** на каждой новой кнопке и значке (правило 9); **место в справке** — текст в разделе `help_<раздел>_body`
    (что это, когда нажимать) и значок с его словами в списке раздела в `shared/src/com/notio/common/HelpMap.kt`;
    **переход из подсказки в справку** — нажатие на показанную подсказку открывает её раздел: ключ текста кнопки
    начинается со слова раздела из `HelpMap.BY_KEY`, иначе раздел задаётся явно (`LocalHelpTopic`, `topic`);
    **контекстный поиск** — справка ищется по словам и показывает найденное в окружении (`HelpMap.search`), поэтому в
    тексте раздела должны стоять слова, которыми функцию будут искать. Функция без подсказки и без справки не
    закончена. Тексты добавляются через `android/translations/add_strings.py`, затем `:desktopApp:syncAndroidStrings`.
12. **Выводы по безопасности ведутся в `docs/SECURITY_RU.md`** (владелец, 2026-10-11; Android D356). Один файл на весь
    репозиторий. Тем же шагом, что и код, туда записывается: каждая проверка безопасности (что смотрели, чем, что не
    проверено); каждая находка — с важностью и исправлением, или как открытый вопрос владельцу; каждая новая,
    обновлённая или убранная библиотека — в таблице библиотек, после сверки её версии с базой известных уязвимостей
    (OSV); каждое изменение того, что касается защиты данных: разрешения и открытые компоненты Android, сеть,
    шифрование, хранение секретов, блокировка, импорт файлов. Таблицы «Текущее состояние», «Открытые вопросы» и
    «Библиотеки» всегда описывают текущий код. В файле не пишется того, что не проверено, как проверенное.

## 3. Сборка (из корня репозитория)

Нужны JDK 25 (для упаковки Windows — JetBrains Runtime SDK 25, см. `windows/DEV_SETUP.md`) и `local.properties` с Android SDK.

```powershell
.\gradlew.bat :app:testDebugUnitTest                      # тесты Android
.\gradlew.bat :windowsShared:jvmTest :desktopApp:jvmTest  # тесты Windows
.\gradlew.bat :app:assembleDebug :app:assembleRelease     # APK
.\gradlew.bat :desktopApp:release                         # MSI, EXE и portable ZIP в dist/
.\gradlew.bat :packageDelivery                            # все пять файлов в dist/
bash tools/publish_delivery.sh tests=<итог тестов>        # затем: подпись release APK и папка поставки с manifest.json
.\gradlew.bat :desktopApp:syncAndroidStrings              # тексты Android -> Windows
./gradlew :desktopApp:releaseLinux                        # на Linux: .bin, .AppImage, .tar.gz и .deb в dist/ (docs/LINUX_RU.md)
```

Версию менять только в `version.properties`. Подпись APK — ключом проекта `private/signing/debug.keystore` (правило 6):
`private/signing/SIGNING_RU.md`, `private/SIGNING_KEYS_RU.md`, `docs/DELIVERY.md`.
