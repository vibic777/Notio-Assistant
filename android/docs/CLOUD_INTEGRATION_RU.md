# Интеграция с Google Диском и Яндекс Диском — итоги (D218, D220, снято в D223)

Состояние на 2026-09-24. Функция сделана в 0.9.36–0.9.39 и **по решению пользователя убрана из приложения** в 0.9.40
(D223): «потратили только время». Код остаётся в истории git — коммит **4fbd00f** с последней версией облачных копий
(«0.9.38-0.9.39: cloud sign-in, diagnostics, battery pass»), его можно поднять, если к облакам вернёмся.

## Что было сделано

**Этап 1 (0.9.36, D218)** — без входа в аккаунт: папка или файл облака выбирались в системном выборе файлов
(Storage Access Framework), файл выгружало само приложение Google Диска / Яндекс Диска. Автоматически раз в день / неделю /
месяц (WorkManager), «Сделать копию сейчас», «Восстановить», строка состояния; копия всегда под паролем.
Замечание пользователя: «где вход в аккаунт? ты сделал не то».

**Этап 2 (0.9.38, D220)** — вход в аккаунт и прямые API:
- Google: Play services `AuthorizationClient` (play-services-auth 22.0.0), доступ только `drive.file`, Drive REST v3, папка
  «Notio backups», resumable upload.
- Яндекс: официальный LoginSDK 3.2.1, доступ к папке приложения, Яндекс Диск REST v1, «Приложения/Notio».
- Ротация 1–9 копий (по умолчанию 5) отдельно для каждого облака, восстановление с выбором копии.
- «Проверить связь» — диагностика по шагам (интернет, регистрация приложения, аккаунт, токен, API, папка,
  запись/чтение/удаление тестового файла, пароль) с копированием отчёта.

**0.9.39 (D221)** — ошибка Google «8 UNREGISTERED_ON_API_CONSOLE» распознаётся как «приложение не зарегистрировано»,
понятные тексты, проверка регистрации в диагностике.

## Результат проверки на телефоне (пользователь, 2026-09-24)

- **Google:** «Не удалось войти: 8, unknown error, UNREGISTERED_ON_API_CONSOLE».
- **Яндекс:** «надо зарегистрировать приложение» (в сборке нет ClientID).

## Почему не заработало

Вход через Google и Яндекс невозможен без **разовой регистрации приложения разработчиком** у каждого сервиса:
- Google Cloud Console: проект, включённый Drive API, экран согласия (тестовые пользователи), OAuth-клиент типа Android
  с пакетом `com.notebudget.app` и SHA-1 ключа подписи (отдельно для debug и release).
- oauth.yandex.ru: приложение с платформой Android (пакет + SHA-256), доступ `cloud_api:disk.app_folder`, ClientID
  вписывается в сборку.

Регистрация не была сделана — без неё оба сервиса отказывают на первом же шаге, и обойти это кодом нельзя.
Подробная пошаговая инструкция была в `docs/CLOUD_SETUP_RU.md` (удалена вместе с функцией, есть в истории git).

## Что стоило времени и выводы

- Этап 1 (выбор папки) не соответствовал ожиданию «интеграции с входом в аккаунт» — надо было сразу уточнить ожидание.
- Для этапа 2 внешняя регистрация — обязательное условие; её стоило сделать (или проверить) **до** написания кода.
- Цена функции: +2,7 МБ APK (Play services auth + Yandex SDK), разрешение INTERNET, фоновые задачи WorkManager.
- Если вернёмся: сначала регистрация у Google и Яндекса и проверка входа на телефоне на минимальном примере,
  потом код (его можно взять из истории git).

## Правило: облака на паузе

пока вы явно не снимете паузу (правило 14 в `docs/AGENT_EN.md`).
