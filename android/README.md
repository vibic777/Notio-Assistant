# Notio by vibic

**English** · [Русский](README_RU.md)

Notio is an offline notebook for Android: folders full of notes of ten kinds — text, lists with prices, budgets, drawings,
blueprints, audio, photos, camera videos, screen recordings and day schedules. Everything is stored **on the phone only**: no
account, no cloud, no analytics, no ads.

> **Status: beta (0.9.x).** The app is feature-complete and covered by ~900 automated tests, but most of it has been checked
> by tests rather than by many people on many phones (the camera, screen recording, overlays and lock-screen alarms in particular).
> Keep a backup (Settings → Backup) of anything you care about. Bug reports are very welcome.

## Features

| Note kind | What it does |
| --- | --- |
| **Text** | Markdown with a formatting toolbar; rendered View first, Edit second; tappable check boxes |
| **List** | Items with quantity, unit and comment; unit totals; a price mode with cost totals; drag to reorder; per-item **Change** buttons (+, −, =) |
| **Budget** | A tree of groups and items with sum / goal / remainder that add up automatically; quantity per item; one **currency** per budget; **Change** button (+, −, =); a **log of changes** that can be exported to TXT / PDF |
| **Drawing** | A raster sheet: pencil, brush, eraser, bucket fill, any colour, zoom to 800 % |
| **Blueprint** | Vector shapes on layers (hide, lock, reorder), fill, zoom |
| **Audio** | Many recordings in one note, each with a name and comment |
| **Photo / Camera video / Screen recording** | Many items per note, full-screen viewer, optional overlays (date and time, place, text, logo) burned into new pictures and videos |
| **Schedule** | Times with descriptions and calculators that show the time between two of them |

Everywhere: folders with colours and styles, tags, search, pins, sorting by twelve keys (per folder), drag-and-drop ordering,
time stamps (optional), a trash with a retention period (also for individual photos, videos and recordings), reminders (snooze,
repeat, alarm-clock screen over the lock screen), an app lock (PIN, password, 3×3 pattern, login, biometrics), optional on-disk
database encryption, export of a single note
(MD, TXT, PDF, JSON, PNG/JPEG, M4A, MP4, ZIP), a full backup with an optional password, light / dark / ten colour themes, adjustable
text size, custom backgrounds, and **ten languages**: English, Русский, Беларуская, Français, Deutsch, Español, Italiano, 中文, 日本語, 한국어
(the translations were written by an AI and have not yet been reviewed by native speakers).

A note-by-note description is in [docs/NOTE_TYPES_RU.md](docs/NOTE_TYPES_RU.md) (Russian); the full functional description is
[docs/FUNCTIONALITY_RU.md](docs/FUNCTIONALITY_RU.md) (Russian).

## Privacy and security

* **Data stays on the device.** Notes live in the app's private storage. `allowBackup` is off, so Android does not copy them to
  the cloud either. There is no server of ours.
* **Network use** is optional and only of two kinds: if you set up an e-mail recovery for the app lock, the app sends a one-time
  code through *your own* SMTP server (STARTTLS or SSL/TLS with certificate **and host name** checks); and **sync between your own
  devices** on the same Wi-Fi (Settings -> Sync), directly between them, encrypted (AES-256-GCM, ECDH keys), only while that page
  is open and only with devices you paired by a code. No internet service, no cloud.
* **Permissions** are asked at the moment of use: microphone (audio, screen recording sound), camera (photo / video), location
  (only if you switch the place stamp on), notifications and exact alarms (reminders), full-screen intents (the alarm screen),
  "display over other apps" (the optional floating Stop button of the screen recorder), biometrics (unlock), internet (the optional
  recovery mail and the local-network sync).
* **App lock:** PIN, password and pattern secrets are stored only as salted PBKDF2-HMAC-SHA256 hashes (210 000 rounds); the
  wrong-attempt wait is configurable and grows up to 15 minutes, with an optional total-attempts limit that either restricts
  entry to recovery only or (opt-in, behind a typed confirmation) wipes the app's own data; screenshots and the recent-apps
  thumbnail are blocked while the lock is on. The lock itself keeps other people out of the app; it does not by itself
  encrypt the database on disk (a 3×3 pattern is also a small secret space) — see database encryption below for that.
* **Database encryption (optional, off by default):** Settings → Data → "Database encryption" converts the database file
  in place with SQLCipher (AES-256); the passphrase is generated by the app (not typed), shown once behind Show/Copy, and
  sealed with the Android Keystore. This protects the database file itself against someone who reads the phone's storage
  directly; it does not (yet) cover media files referenced by the database. A separate raw-file export/import exists next
  to the regular backup, for moving the encrypted file itself.
* **Backups** can be protected with a password: AES-256-GCM, key from PBKDF2-HMAC-SHA256 (600 000 rounds). A forgotten backup
  password cannot be recovered. Backups contain no lock secrets and no mail password.
* Details and a security review: [docs/SECURITY_REVIEW.md](docs/SECURITY_REVIEW.md). To report a vulnerability see [SECURITY.md](SECURITY.md).

## Install

Requires Android 9 (API 28) or newer (built for Android 16, compiled against the Android 17 SDK).

1. Download the latest `Notio-by-vibic-<version>.apk` from the **Releases** page.
2. Allow installing from the source you opened it from (Android asks).
3. Open the APK. Updates install over the previous version as long as the APK is signed with the same key.

## Build from source

The app is the `android/` folder of the Notio repository and is built from the repository root. You need **JDK 21 or 25** and the Android SDK (platform 37, build tools).

```bash
git clone <this repository>
cd <folder>
# create local.properties with your SDK location, e.g.  sdk.dir=/path/to/Android/Sdk
./gradlew :app:assembleDebug        # android/app/build/outputs/apk/debug/Notio-by-vibic-<version>-debug.apk
./gradlew :app:testDebugUnitTest    # the automated tests (JVM + Robolectric), about 2 minutes
```

A release build is signed only if a `keystore.properties` file (never committed) points to your key:

```properties
storeFile=/path/to/your.jks
storePassword=...
keyAlias=...
keyPassword=...
```

then `./gradlew :app:assembleRelease`. Do **not** commit keys or passwords.

There is no emulator requirement for the tests. The UI tests run on the JVM with Robolectric.

## How the code is organised

Kotlin, Jetpack Compose (Material 3), Room (schema exported to `app/schemas`, every version has a tested migration), DataStore,
kotlinx.serialization, CameraX, Media3 Transformer, manual dependency injection (`AppContainer`).

```
app/src/main/java/com/notebudget/app/
  core/      database, datastore, alarms and notifications, security (hashing, TOTP, Keystore), mail, UI building blocks, theme
  domain/    models, repository interfaces, use cases (no Android types where avoidable)
  data/      Room repositories, backup / import / export, file stores
  feature/   one package per screen or note kind (home, budget, notes/list, drawing, audio, media, settings, ...)
translations/  ten languages; ru/fr/de are edited in res/values-*, the rest are generated from translations/src/*.tsv
docs/          functional description, the design decisions log, checklists
```

A new note kind is one `NoteTypeDefinition` class plus one line in `AppContainer.noteTypes`.
Backups and export files are tolerant by design: every field has a default, unknown fields are ignored and unknown note kinds are kept,
so files from older and newer versions keep loading.
