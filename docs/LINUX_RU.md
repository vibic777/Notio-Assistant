# Notio под Linux: состояние и сборка

Настольное приложение Linux — тот же код, что и Windows (`windows/desktopApp`, `windows/shared`): Kotlin и Compose Desktop.
Отдельного Linux-кода нет и по плану быть не должно; отличается только то, что зависит от системы. План и журнал решений
Linux-версии — `linux/AGENT.md` (перенесён из `D:\Notio-Linux`, там был только план).

**Состояние на 2026-10-11: собрано, запущено и проверено тестами в WSL 2** (Ubuntu 24.04, JetBrains Runtime SDK 25 для
Linux; решения Windows D129, Linux D12). Все четыре файла собираются и запускаются; тесты настольного приложения на
Linux проходят. **На настоящем рабочем столе Linux (GNOME, KDE) не проверялось ничего**: в WSL нет трея, нет OpenGL для
окна (рисуется программно) и нет звука напоминаний.

## Что нашла первая сборка и что исправлено

| Что было | Что сделано |
| --- | --- |
| Проект не настраивался без Android SDK | на машине без SDK Android-проект не подключается |
| `bin/Notio: Permission denied` — архивы теряли права на файлы | архивы хранят права |
| «Could not find or load main class» — в `Notio.cfg` были окончания строк Windows | файл пишется с окончаниями строк своей системы |
| «Запускать вместе с системой» ничего не делал | файл `~/.config/autostart/notio.desktop` |
| «Закрыть в трей» прятало окно там, где трея нет | окно сворачивается, Notio продолжает работать |
| Уведомления шли только через значок в трее | без трея — через `notify-send` |
| Notio объявлял себя на виртуальных адаптерах (docker, virbr, tun, wg…) | они узнаются по имени и пропускаются |
| Значок напоминаний и ещё семь значков-эмодзи были пустыми прямоугольниками там, где нет шрифта с эмодзи | приложение спрашивает систему и рисует свой значок или простой знак; `.deb` требует шрифт с эмодзи |
| На другом компьютере `.bin` падал до окна (`SIGSEGV` в `getenv`), перед этим — предупреждения JVM о кэше AOT | с 0.9.55 в кэше быстрого запуска только классы, без машинного кода; запуск без кэша: `JAVA_TOOL_OPTIONS=-XX:AOTMode=off` |
| Папку данных (`~/.local/share/notio`) мог прочитать любой пользователь компьютера, а секреты на Linux лежат в ней без системного хранилища | с 0.9.52 папка закрыта для всех, кроме владельца (`rwx------`), при каждом запуске |

## Как это работает «как сервис»

Как на Windows: включить «Запускать вместе с Linux» и «Запускать свёрнутым в трей» (Настройки → Общие) и «Всегда
готов к синхронизации» (страница синхронизации). Notio стартует при входе в систему, сидит в трее (или свёрнутым,
если трея нет), ждёт синхронизацию и звонит напоминаниями, пока запущен. Запуска совсем без окна — для машины без
монитора — нет (Linux D11, не сделано).

## Что уже готово

- Сборка знает о Linux: `:desktopApp:releaseLinux` кладёт в `dist/` все четыре варианта (таблица ниже); корневая
  `:packageLinuxDelivery` добавляет два APK. На Windows они пропускаются; установщики Windows на Linux не собираются.
- `gradlew` помечен исполняемым.
- Папка данных: `~/.local/share/notio`; переносимая сборка хранит данные в `Notio/data` рядом с `portable.txt`.
- Код, зависящий от Windows, уже обходится без неё: способ отрисовки, часы блокировки, запись через Media Foundation,
  автозапуск, DPAPI проверяют систему и на Linux не вызываются.
- CI: job `linux` в `.github/workflows/build.yml` собирает `.deb` и архив на Ubuntu (ни разу не запускался).

## Четыре варианта поставки

| Файл | Задача | Как пользоваться | Где данные |
| --- | --- | --- | --- |
| `Notio-<версия>-linux-x64.bin` | `packageLinuxBin` | **один файл: `chmod +x` и запустить** | папка `Notio-data` рядом с файлом |
| `Notio-<версия>-x86_64.AppImage` | `packageLinuxAppImage` | один файл: `chmod +x` и запустить | `~/.local/share/notio` |
| `Notio-<версия>-linux-x64.tar.gz` | `packageLinuxPortable` | распаковать, запустить `Notio/bin/Notio` | `Notio/data` рядом с `portable.txt` |
| `notio_<версия>_amd64.deb` | `packageLinuxDeb` | `sudo apt install ./notio_….deb` | `~/.local/share/notio` |
| `notio-<версия>-1.x86_64.rpm` | `packageLinuxRpm` | Fedora, openSUSE, RHEL: `sudo dnf install ./notio-….rpm`; для сборки нужен `rpmbuild` (`sudo apt install rpm`) | `~/.local/share/notio` |

Файл `.bin` — небольшой скрипт с упакованной папкой приложения после последней строки (`windows/desktopApp/linux/notio-bin-stub.sh`). При первом запуске он распаковывает приложение в `~/.cache/notio` (около 250 МБ), дальше запускает оттуда сразу; распакованное прежней версией удаляется. Если папка, где лежит файл, недоступна для записи, данные идут в `~/.local/share/notio`. Место данных можно задать переменной `NOTIO_HOME`. Сам скрипт проверен на подставной папке приложения (распаковка, повторный запуск, путь с пробелом, аргументы); с настоящим приложением на Linux — нет.

AppImage собирает `appimagetool`: сборка скачивает его с GitHub при первом запуске задачи (нужен интернет). Не проверялось.

## Что на Linux будет работать не так, как на Windows

| Часть | На Linux сейчас | Что сделать |
| --- | --- | --- |
| Секреты (пароль копий, ключи синхронизации, почта) | хранятся без шифрования системой («Plain») | Secret Service / libsecret (`linux/AGENT.md` D04) |
| Запись с камеры, видео, запись экрана | недоступна: заметки открываются, запись выключена | своя реализация (GStreamer / PipeWire) |
| Запись голоса и воспроизведение аудиозаметок | недоступны: кодер и плеер — Windows Media Foundation; запись пишет ошибку в журнал | своя реализация (GStreamer или ffmpeg) |
| Автозапуск вместе с системой | есть с 0.9.51: файл в `~/.config/autostart` | проверить на GNOME и KDE |
| Заголовок окна в стиле приложения | системный заголовок | оставить системный |
| Трей, уведомления, звук будильника | не проверялось | проверить в GNOME и KDE |
| Закрытие запущенного Notio установщиком | нет (это действие MSI) | не нужно: `.deb` ставит пакетный менеджер |
| Версия | общая с Windows (`windows.version`) | отдельная линия `linux.*`, когда версии разойдутся |

## Сборка в WSL (Ubuntu 22.04 или новее)

1. В Windows: `wsl --install -d Ubuntu`, перезагрузка.
2. В Ubuntu поставить инструменты:

   ```bash
   sudo apt update
   sudo apt install -y git unzip fakeroot dpkg-dev binutils libgl1 libxi6 libxrender1 libxtst6 fonts-dejavu
   ```

3. Поставить JDK 25 с `jpackage` для Linux (JetBrains Runtime SDK 25 для linux-x64 или Temurin 25) и указать его:

   ```bash
   export JAVA_HOME=$HOME/jdks/jbrsdk-25-linux-x64
   export PATH=$JAVA_HOME/bin:$PATH
   ```

4. Получить репозиторий **внутри файловой системы Linux** (не в `/mnt/d/...`: там сборка в разы медленнее и теряются права
   на файлы):

   ```bash
   git clone /mnt/d/transfer/Notio.bundle ~/Notio     # или git clone с другой машины / с GitHub
   cd ~/Notio
   git config user.name vibic777 && git config user.email vibic@yandex.ru
   ```

5. Собрать:

   ```bash
   ./gradlew :windowsShared:jvmTest :desktopApp:jvmTest   # тесты (нужен дисплей: WSLg в Windows 11 даёт его сам)
   ./gradlew :desktopApp:releaseLinux                     # dist/: .bin, .AppImage, .tar.gz и .deb
   ```

   Для APK в WSL нужен ещё Android SDK для Linux и `local.properties` с `sdk.dir`; проще собирать APK в Windows.
   Без Android SDK сборка может остановиться на настройке проекта `:app` — тогда указать SDK или собирать настольную часть
   на машине, где он есть.

6. Проверить:

   ```bash
   chmod +x dist/Notio-*-linux-x64.bin && ./dist/Notio-*-linux-x64.bin     # один файл
   chmod +x dist/Notio-*.AppImage && ./dist/Notio-*.AppImage               # AppImage
   sudo apt install ./dist/notio_*_amd64.deb && /opt/notio/bin/Notio
   tar -xzf dist/Notio-*-linux-x64.tar.gz -C /tmp && /tmp/Notio/bin/Notio
   ```

## Чего ждать при первой сборке

Это первый запуск на Linux, поэтому ошибки вероятны. Места, где их стоит ждать в первую очередь:

- тесты, которые опираются на Windows (пути, звук, окна);
- обучение AOT-кэша: без дисплея сборка идёт дальше с предупреждением, Notio просто стартует медленнее;
- трей и уведомления в конкретном окружении рабочего стола;
- шрифты и ввод в полях (IME).

Найденное записывать в `linux/AGENT.md` и в `docs/TODO_RU.md`.
