# План: синхронизация Notio через Google Диск

Состояние: **план, кода нет** (2026-10-05; Android D313). Облачные сервисы на паузе (правило 10 корневого `AGENT.md`);
работа начинается только после того, как владелец снимет паузу и выполнит раздел 2. Прежняя попытка и её выводы —
`android/docs/CLOUD_INTEGRATION_RU.md`; её код — коммит `187ae2f` (вход через Google Play services, Drive REST v3).

Сведения о правилах Google записаны по памяти; всё, что помечено «проверить», сверяется с действующей документацией
на этапе 0, до кода.

## 1. Что получится

- В Настройки → Синхронизация появляется «Google Диск»: «Войти», «Синхронизировать», «Выйти», строка состояния.
- Данные лежат в скрытой папке приложения на Диске владельца (`appDataFolder`, доступ `drive.appdata`): Notio видит только
  её, остальной Диск ему недоступен; человек в интерфейсе Диска эти файлы не видит, только занятый ими объём.
  Вариант — видимая папка «Notio» с доступом `drive.file` (только файлы, созданные самим Notio). **Решить** на этапе 0;
  рекомендация — скрытая папка: файлы нельзя случайно удалить или переименовать руками.
- Всё, что уходит на Диск, зашифровано на устройстве паролем синхронизации (формат защищённой резервной копии
  `.json.zip.enc`). Google хранит файлы, прочитать их не может. Без пароля данные с Диска не восстановить.
- Синхронизация идёт по нажатию кнопки. Фоновой работы нет (правило 2).

## 2. Что нужно от владельца до начала

1. **Снять паузу** с облачных сервисов (правило 10).
2. **Учётная запись Google**, от имени которой создаётся проект.
3. **Проект в Google Cloud Console** (один раз, вместе, по шагам этапа 0):
   - создать проект, включить Google Drive API;
   - экран согласия: тип «Внешний», название «Notio by vibic», адрес почты, доступы `drive.appdata` (или `drive.file`);
   - OAuth-клиент типа **Android**: пакет `com.notebudget.app` и отпечаток **SHA-1** ключа подписи — отдельный клиент
     для отладочного ключа и для релизного;
   - OAuth-клиент типа **«Приложение для компьютера»** — для Windows и Linux;
   - для Linux без монитора — клиент типа «Телевизоры и устройства с ограниченным вводом».
4. **Режим экрана согласия.** В режиме «Тестирование» входить могут только добавленные вручную тестовые пользователи, и вход
   нужно повторять примерно раз в неделю. Для постоянной работы экран переводится в «Рабочий» режим; для этого Google просит
   **страницу приложения и политику конфиденциальности по общедоступному адресу**. Доступы `drive.appdata` и `drive.file`
   не относятся к ограниченным, платная проверка безопасности для них не нужна. **Проверить** действующие требования на этапе 0.
5. **Решить вопрос ключа подписи** (`docs/TODO_RU.md`, раздел 2): отпечаток входит в регистрацию. Смена ключа позже —
   новый OAuth-клиент, иначе вход на телефоне перестанет работать (ошибка «UNREGISTERED_ON_API_CONSOLE», как в D221).
6. **Телефон с сервисами Google Play** для проверки входа на этапе 0. На телефоне без них этот способ входа не работает.

## 3. Как устроена синхронизация (общее с планом Яндекса)

Сервера у Notio нет, поэтому облако работает как общий почтовый ящик, а объединяет данные само устройство — тем же кодом,
что уже объединяет данные при синхронизации по сети и при импорте копии (`ImportPlanner`, режим «слияние»: новее побеждает).

- У каждого устройства свой файл-снимок `devices/<id устройства>.notio.enc` в папке приложения.
- «Синхронизировать»: (1) скачать снимки других устройств, которые изменились с прошлого раза; (2) слить их с данными
  устройства; (3) выгрузить свой новый снимок.
- Вложения (фото, видео, аудио, рисунки) в снимок не входят: они лежат отдельными зашифрованными файлами `media/<id>`
  и передаются только те, которых на другой стороне нет.
- Каждое устройство пишет только свой файл: конфликтов записи нет.

**Проверить до кода:** как слияние переносит удаление заметки с одного устройства на другое; без этого удалённая заметка
будет возвращаться.

## 4. Android

- Вход: `AuthorizationClient` из Google Play services (`play-services-auth`) с запросом нужного доступа; приложение получает
  токен доступа и при необходимости запрашивает его снова без участия человека. Секретов приложения в сборке нет.
- Диск: Drive REST v3 — список файлов папки приложения, выгрузка с продолжением после обрыва (resumable upload), скачивание.
- Цена: прежняя попытка добавила к APK около 2,7 МБ на оба облака вместе; разрешение INTERNET уже есть.
- Без WorkManager и без расписания: только кнопка.

## 5. Windows и Linux

- Вход: открывается браузер, после согласия Google возвращает код на локальный адрес `http://127.0.0.1:<порт>`, который
  Notio слушает только на время входа; код меняется на токены (OAuth с PKCE). Токен обновления хранится под DPAPI (Windows)
  и в Secret Service (Linux; защита секретов на Linux — отдельный пункт `docs/TODO_RU.md`, раздел 1а, делается раньше).
- Linux без монитора: вход по коду устройства — Notio печатает адрес и короткий код, человек вводит его на телефоне.
  Этот способ Google разрешает только для части доступов; `drive.appdata` и `drive.file` в неё входят — **проверить** на этапе 0.
- Работа с Диском — тот же REST API; код общий с Android насколько позволяет `shared/src`.

## 6. Этапы

| Этап | Что делается | Чем заканчивается |
| --- | --- | --- |
| 0 | Проект, экран согласия, OAuth-клиенты; на телефоне проверяется только вход и запись одного тестового файла | Вход работает на телефоне владельца. Без этого дальше не идём — урок D223 |
| 1 | Android: вход, выход, «Проверить связь», облачная копия вручную (выгрузить, показать список, восстановить) | Копия с телефона восстанавливается на том же телефоне |
| 2 | Android: синхронизация по разделу 3 | Два телефона сходятся к одним данным |
| 3 | Windows: вход через браузер и та же синхронизация | Телефон и компьютер сходятся |
| 4 | Linux, в том числе без монитора | Узел Linux сходится с остальными |
| 5 | Перевод экрана согласия в «Рабочий» режим (страница приложения, политика конфиденциальности) | Вход не нужно повторять каждую неделю; входить может любой пользователь |

Каждый этап — своё решение в журнале, своя версия, все формы поставки, проверка на устройстве.

## 7. Риски и открытые вопросы

- **Регистрация.** Без неё вход невозможен, обойти кодом нельзя (D223).
- **Режим «Тестирование»** годится для разработки и личного использования, но требует повторного входа; постоянная работа
  требует общедоступной страницы и политики конфиденциальности — а удалённого репозитория и сайта у проекта пока нет.
- **Ключ подписи.** Смена ключа ломает вход на Android до создания нового OAuth-клиента.
- **Телефоны без сервисов Google Play** этим способом войти не могут.
- **Пароль синхронизации.** Потерян — данные на Диске не прочитать.
- **Квота Диска** общая с почтой и фото владельца; видео её быстро занимает. Нужен показ занятого объёма.
- **Решить:** скрытая папка приложения или видимая папка «Notio».
- **Решить:** пароль синхронизации — отдельный или тот же, что у резервной копии.
- **Решить:** Яндекс и Google одновременно или по одному облаку на устройство; с какого начинать.
  Рекомендация — с Яндекса: регистрация проще, нет режима тестирования и требования политики конфиденциальности.
