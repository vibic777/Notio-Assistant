# План: помощник — управление Notio словами через локальную модель

Состояние: **план; первый кусок кода есть на ветке `assistant`** (владелец, 2026-10-13: «попробуем реализовать, как
параллельное развитие, ответвление от стандартной версии»). Что сделано — в разделе «Ход работ» в конце. **Это отдельная линия на будущее, не часть основной
разработки** (владелец, 2026-10-13): в списки дел и в планы версий Android, Windows и Linux она не входит, пока
владелец не скажет начать. Здесь собрано всё о новой возможности, чтобы она не терялась среди текущих правок.

Не все решения из раздела 13 приняты; номера решений в журналах
платформ появятся, когда владелец их примет. Telegram из раздела 6 — облачный сервис: он под паузой правила 10
корневого `AGENT.md`, пока владелец её не снимет.

Сведения о LM Studio и MCP записаны по памяти об их устройстве; всё, что помечено «проверить», сверяется с
документацией и на машине владельца на этапе 0, до кода.

## 1. Что получится

Вы пишете обычными словами: «отсортируй заметки в папке Работа по дате», «покажи заметку про банк», «создай список
покупок: молоко, хлеб», «разложи заметки по папкам». Notio это выполняет. Каждое такое поручение записано в журнал, и
любое можно откатить одной кнопкой, если модель сделала не то.

Модель работает **на вашем компьютере** (LM Studio). Заметки никуда не уходят — кроме варианта с Telegram, о нём
отдельно в разделе 6.

## 2. Главная мысль в одной картинке

Модель **не лезет в базу заметок**. Она умеет только одно: попросить Notio выполнить команду из готового списка.
Выполняет команду сам Notio — тем же кодом, каким он выполняет ваши нажатия.

```
   ВЫ                    МОДЕЛЬ                        NOTIO
   пишете слова          понимает слова                делает дело

 ┌──────────────┐      ┌──────────────────┐      ┌─────────────────────────┐
 │ «отсортируй  │      │  LM Studio       │      │  список команд          │
 │  папку       │ ───► │  (локальная      │ ───► │  sort_folder(…)         │
 │  Работа      │      │   модель)        │      │  create_note(…)         │
 │  по дате»    │      │                  │      │  move_note(…)  …        │
 └──────────────┘      │  отвечает НЕ     │      ├─────────────────────────┤
                       │  текстом, а:     │      │  журнал с откатом       │
        ▲              │  «вызови         │      ├─────────────────────────┤
        │              │   sort_folder    │      │  база заметок           │
        │              │   папка=Работа   │      └─────────────────────────┘
        │              │   ключ=дата»     │                  │
        │              └──────────────────┘                  │
        └───────────────── «Готово: 12 заметок» ◄────────────┘
```

Отсюда три следствия, на которых держится весь план:

- модель не может сделать того, чего нет в списке команд (окончательного удаления в списке нет);
- каждая команда проходит те же проверки, что и ваше нажатие (пустое название, чужая папка и так далее);
- каждая команда проходит через журнал, поэтому её можно отменить.

## 3. Слои: кто за что отвечает

Слой — это часть программы со своей одной задачей. Сверху вниз: чем выше, тем ближе к вам; чем ниже, тем ближе к
данным. Каждый слой разговаривает только с соседним.

```
 ┌───────────────────────────────────────────────────────────────────────┐
 │ 1. ВХОД — откуда пришли слова                                         │
 │    чат в окне Notio   │   программа с MCP (LM Studio)   │   Telegram  │
 └───────────────────────────────────────────────────────────────────────┘
                                   │  текст поручения
                                   ▼
 ┌───────────────────────────────────────────────────────────────────────┐
 │ 2. МОДЕЛЬ — LM Studio на вашем компьютере, адрес вида …/v1            │
 │    превращает слова в вызовы команд                                   │
 └───────────────────────────────────────────────────────────────────────┘
                                   │  «вызови команду X с параметрами Y»
                                   ▼
 ┌───────────────────────────────────────────────────────────────────────┐
 │ 3. КОМАНДЫ — новый слой Notio (его надо написать)                     │
 │    список разрешённых действий, проверка параметров, права, лимиты;   │
 │    права помощника (раздел 9) и уровни заметок (раздел 8) — здесь     │
 └───────────────────────────────────────────────────────────────────────┘
                                   │  проверенная команда
                                   ▼
 ┌───────────────────────────────────────────────────────────────────────┐
 │ 4. ЖУРНАЛ С ОТКАТОМ — новый слой Notio (его надо написать)            │
 │    перед изменением запоминает, как было; хранит записи поручений     │
 └───────────────────────────────────────────────────────────────────────┘
                                   │  «теперь меняй»
                                   ▼
 ┌───────────────────────────────────────────────────────────────────────┐
 │ 5. ДЕЙСТВИЯ NOTIO — уже есть                                          │
 │    создать / изменить / переместить заметку, сортировка, корзина      │
 └───────────────────────────────────────────────────────────────────────┘
                                   │
                                   ▼
 ┌───────────────────────────────────────────────────────────────────────┐
 │ 6. ДАННЫЕ — уже есть: база заметок и файлы на устройстве              │
 └───────────────────────────────────────────────────────────────────────┘
```

| Слой | Что это простыми словами | Есть сейчас? | Где живёт |
| --- | --- | --- | --- |
| 1. Вход | Окошко, куда вы пишете | Нет | Notio, LM Studio или Telegram — по выбору |
| 2. Модель | «Переводчик» со слов на команды | У вас — LM Studio | Отдельная программа на компьютере |
| 3. Команды | Меню разрешённых действий | Нет, пишем | Внутри Notio |
| 4. Журнал | Память «как было» и кнопка «Откатить» | Нет, пишем | Внутри Notio, отдельный файл |
| 5. Действия | То, что Notio делает по вашим нажатиям | Да | Внутри Notio |
| 6. Данные | Сами заметки | Да | База и файлы на устройстве |

Писать предстоит слои 1, 3 и 4. Слой 2 — готовая чужая программа. Слои 5 и 6 не меняются.

## 4. Одно поручение по шагам

Поручение: «отсортируй заметки в папке Работа по дате».

```
  Вы            Вход           Модель          Команды         Журнал        Действия
  │              │               │               │               │              │
  │ «отсортируй» │               │               │               │              │
  ├─────────────►│  слова +      │               │               │              │
  │              │  список команд│               │               │              │
  │              ├──────────────►│               │               │              │
  │              │               │ list_folders  │               │              │
  │              │               ├──────────────►│  читать можно │              │
  │              │               │               ├──────────────────────────────►
  │              │               │  [Дом, Работа]│◄──────────────────────────────┤
  │              │               │◄──────────────┤               │              │
  │              │               │ sort_folder   │               │              │
  │              │               │ (Работа, дата)│               │              │
  │              │               ├──────────────►│ проверка      │              │
  │              │               │               ├──────────────►│ запомнить,   │
  │              │               │               │               │ как было     │
  │              │               │               │               ├─────────────►│ сортировка
  │              │               │      готово   │◄──────────────┴──────────────┤
  │              │               │◄──────────────┤               │              │
  │              │ «Готово, 12»  │               │               │              │
  │◄─────────────┤◄──────────────┤               │               │              │
```

Что здесь важно:

- Модель сначала **спрашивает** (какие есть папки), потом **действует**. Она не знает вашу базу заранее.
- Читать можно сразу. Перед изменением слой команд проверяет параметры, а журнал запоминает прежнее состояние.
- Ответ вам пишет модель, но по результату, который вернул Notio, а не «из головы».

## 5. Список команд (слой 3)

Команда — это действие с названием и параметрами. Черновик первого набора:

| Группа | Команды | Меняет данные? |
| --- | --- | --- |
| Чтение | список папок; список заметок папки (порциями); поиск; прочитать заметку | Нет |
| Заметки | создать; переименовать; заменить или дописать текст; переместить; метки; цвет; закрепить; в корзину | Да |
| Папки | создать; переименовать; сортировка; ручной порядок | Да |
| По видам заметок | пункт списка: добавить, отметить; задача: статус, сроки; бюджет: изменить сумму | Да |
| Экран | открыть папку; открыть заметку; включить поиск | Нет (только вид) |
| Оформление | тема, цвета, размер шрифта, вид карточек, фон | Да (настройки) |
| Настройки приложения | язык и форматы дат, предпросмотр, штампы, корзина, сообщения внизу экрана | Да (настройки) |

Какие группы команд помощнику разрешены, задаёте вы — на экране «Права помощника» (раздел 9). По умолчанию не
разрешено ничего.

Чего в списке **нет и не будет**, какие бы права ни стояли: очистка корзины, окончательное удаление, настройки
блокировки и шифрования, пароли, сопряжение устройств для синхронизации, сами права помощника и уровни доступа
заметок. Модель не может попросить то, чего нет в меню.

Сложные поручения — это цепочки простых команд. «Систематизируй заметки»:

```
 прочитать названия ─► модель предлагает раскладку ─► Notio показывает её вам ─► «Применить»? ─► перемещения
   (чтение)              (ничего не меняется)           (таблица: что куда)         (ваше «да»)    (одна запись журнала)
```

## 6. Три входа (слой 1)

Слои 3–6 у всех трёх вариантов **одни и те же**. Отличается только то, где вы пишете и кто разговаривает с моделью.

### Вариант А — чат в окне Notio

```
 ┌──────────────────────── ваш компьютер ────────────────────────┐
 │                                                               │
 │   ┌─────────────────────┐   запрос по сети    ┌────────────┐  │
 │   │ Notio               │   внутри компьютера │ LM Studio  │  │
 │   │  ┌───────────────┐  │ ──────────────────► │  модель    │  │
 │   │  │ чат           │  │ ◄────────────────── │            │  │
 │   │  ├───────────────┤  │   «вызови команду»  └────────────┘  │
 │   │  │ команды       │  │                                     │
 │   │  │ журнал        │  │                                     │
 │   │  │ заметки       │  │                                     │
 │   │  └───────────────┘  │                                     │
 │   └─────────────────────┘                                     │
 └───────────────────────────────────────────────────────────────┘
```

Notio сам обращается к LM Studio. Наружу ничего не открыто. Это самый простой и самый закрытый вариант.

### Вариант Б — MCP: Notio как «набор инструментов» для другой программы

MCP — это общий язык, на котором программа с моделью спрашивает другую программу: «какие у тебя есть команды?» и
«выполни вот эту». Notio становится MCP-сервером: он ничего не спрашивает у модели сам, он только отвечает.

```
 ┌──────────────────────── ваш компьютер ────────────────────────┐
 │                                                               │
 │   ┌────────────────────┐   MCP: «какие     ┌──────────────┐   │
 │   │ LM Studio          │   команды есть?»  │ Notio        │   │
 │   │  чат (пишете тут)  │ ────────────────► │  MCP-сервер  │   │
 │   │  модель            │   «выполни        │  команды     │   │
 │   │                    │    sort_folder»   │  журнал      │   │
 │   │                    │ ◄──────────────── │  заметки     │   │
 │   └────────────────────┘     результат     └──────────────┘   │
 │                              только с этого компьютера,       │
 │                              по секретному ключу              │
 └───────────────────────────────────────────────────────────────┘
```

Чат — в LM Studio или в любой другой программе, которая понимает MCP. Notio при этом может быть свёрнут в трей.
Цена: у Notio появляется вход для других программ, его надо закрыть ключом и не выпускать за пределы компьютера.

### Вариант В — Telegram-бот

```
  телефон                интернет                 ваш компьютер (должен быть включён)
 ┌─────────┐         ┌──────────────┐        ┌────────────────────────────────────────┐
 │Telegram │ ──────► │ серверы      │ ─────► │ бот ──► LM Studio ──► команды Notio    │
 │ вы      │ ◄────── │ Telegram     │ ◄───── │  ▲                         │           │
 └─────────┘         └──────────────┘        │  └──────── результат ◄─────┘           │
                      ▲                      └────────────────────────────────────────┘
                      │
            здесь проходит текст ваших
            поручений и ответов с заметками
```

Удобно: управление с телефона откуда угодно. Но есть три вещи, которые надо принять осознанно:

- текст поручений и ответов (а значит, и содержимое заметок, которые вы просите показать) проходит через серверы
  Telegram — это облачный сервис, сейчас под паузой правила 10;
- работает, только пока включён компьютер с Notio и LM Studio;
- бот должен слушать только вас (ваш идентификатор в Telegram), иначе любой, кто найдёт бота, управляет заметками.

**Мысль владельца (2026-10-13): напоминания в Telegram.** Когда в Notio срабатывает напоминание, бот присылает
сообщение в Telegram. Это отдельная и простая часть: модель для неё не нужна, бот только пересылает.

Отдавать ли напоминания заметки в Telegram — **свой переключатель на заметке**, отдельный от уровня доступа (владелец,
2026-10-13). Так заметку можно оставить закрытой от помощника и при этом получать её напоминания на телефон:

| На заметке | Что приходит в Telegram, когда срабатывает напоминание |
| --- | --- |
| «Напоминания в Telegram» выключено (по умолчанию) | Ничего: напоминание звонит в самом Notio, как сейчас |
| Включено | Текст самого напоминания; содержимое заметки не прикладывается |

Переключатель есть и на папке: вместе с уровнем доступа он ставится всем заметкам папки кнопкой «Применить ко всем
заметкам» (раздел 8). Как и весь вариант В, ждёт снятия облачной паузы и работает, пока включён компьютер.

### Голос, фото и рисунки через бота — мысль на потом

Мысль владельца (2026-10-13): боту можно прислать не только слова. Голосовое сообщение — сохранить аудиозаметкой или
распознать и сделать из него заметку, список, расписание, строку бюджета. Фото — сохранить фотозаметкой или описать,
что на нём. И попросить нарисовать чертёж или рисунок.

| Что прислали или попросили | Что получается в Notio | Что для этого нужно | Насколько это реально |
| --- | --- | --- | --- |
| Голосовое сообщение, «сохрани» | Аудиозаметка с этой записью | Бот скачивает файл и кладёт его в заметку | Просто: модель не нужна |
| Голосовое сообщение, «запиши как заметку / список» | Текстовая заметка, заметка MD, список, расписание | Модель распознавания речи на компьютере (отдельная от той, что в чате); затем обычные команды | Реально; новая часть — распознавание речи. Умеет ли это LM Studio — проверить |
| Голос: «добавь в бюджет хлеб 50» | Строка бюджета | То же, плюс команды бюджета (их ещё нет) | Реально, но суммы — место, где ошибка модели дороже всего (раздел 11, п. 10): только с подтверждением |
| Фото, «сохрани» | Фотозаметка | Бот скачивает файл и кладёт его в заметку | Просто: модель не нужна |
| Фото, «что тут?» / «запиши, что на фото» | Заметка с описанием или с текстом с фото | Модель, которая понимает картинки; такие в LM Studio есть | Реально при подходящей модели |
| «Нарисуй чертёж: комната 3 на 4» | Чертёж из линий и фигур | Команды «добавить фигуру» для чертежа; модель задаёт координаты | Реально для простых схем: чертёж в Notio — это фигуры, а не картинка |
| «Нарисуй рисунок: кот» | Рисунок-картинка | Модель, которая создаёт изображения, — другой вид моделей | Отдельная большая тема; в план этапов не входит |

**Уточнение владельца (2026-10-14).** Любой контент — в чат Notio и в бота — и у каждого вида свой выбор:

| Что прислали | Вариант 1 | Вариант 2 |
| --- | --- | --- |
| Аудио (голосовое, файл) | Сохранить в аудиозаметку | Распознать в текст — **только по явной просьбе человека** («распознай», «запиши текстом»), затем, если попросил, перевести |
| Фото | Сохранить в фотозаметку | Распознать или описать — тоже только по явной просьбе |
| Видео | Сохранить в видеозаметку | Распознавания нет и не планируется пока: слишком дорого. Только сохранение |

По умолчанию, без просьбы, файл просто сохраняется в заметку своего вида. **Голосовой ввод** — на всех трёх системах:
Android, Windows, Linux (раздел 10, «Голосовой ввод»).

Общее для всего этого: файлы идут через Telegram (пауза правила 10; пределы размера у ботов — проверить); всё, что
бот создал, пишется в журнал и откатывается; каждая новая возможность — своё право в списке прав (раздел 9), а
заметка, созданная из Telegram, открыта для Telegram (раздел 8).

### Какая модель: своя или внешняя

Принято владельцем (2026-10-13): Notio подключается к **любой модели, которая говорит на том же языке, что и LM
Studio** (адрес вида `…/v1`, с ключом или без). Это может быть:

```
   ГДЕ МОДЕЛЬ                          КУДА УХОДИТ ТЕКСТ ЗАМЕТОК            В НАСТРОЙКАХ ПОДПИСАНО

 ┌─────────────────────────┐
 │ на этом компьютере      │  ───►   никуда: остаётся на компьютере      «Этот компьютер»
 │ (LM Studio рядом с Notio)│
 └─────────────────────────┘
 ┌─────────────────────────┐
 │ на другом компьютере    │  ───►   по домашней сети на ваш же          «Домашняя сеть»
 │ в домашней сети         │         компьютер
 └─────────────────────────┘
 ┌─────────────────────────┐
 │ внешний сервис          │  ───►   в интернет, на чужие серверы        «Внешний сервис: заметки
 │ (например, OpenRouter)  │                                              уходят за пределы ваших
 └─────────────────────────┘                                              устройств»
```

Notio сам определяет по адресу, какой это случай, и пишет подпись рядом с адресом. Ключ внешнего сервиса хранится
запечатанным, как остальные секреты Notio.

**Адрес и ключ в настройках** (владелец, 2026-10-13): адрес вписывается целиком, вместе с портом
(`http://127.0.0.1:1234/v1`, порт может быть любым). Ключ после сохранения показан точками; рядом «Показать» и
«Копировать» — чтобы ключ не потерять. Так же в Notio уже показан пароль базы.

Чем внешняя модель лучше и чем хуже:

| | Своя модель (LM Studio) | Внешний сервис |
| --- | --- | --- |
| Заметки покидают ваши устройства | Нет | Да — всё, что модель читает |
| Насколько точно выполняет поручения | Зависит от модели; небольшие ошибаются чаще | Обычно заметно точнее |
| Работает на телефоне без компьютера | Только дома, в одной сети с компьютером | Да, везде, где есть интернет |
| Стоит денег | Нет | Да, за каждое обращение; Notio счёт не видит |
| Облачная пауза (правило 10) | Не касается | **Касается:** это облачный сервис, нужен снятый запрет |

**Правило, которое связывает модель и доступ к заметкам (раздел 8):** внешней модели отдаются только заметки с
«Можно внешней модели», в Telegram — только заметки с «Можно в Telegram». Если поручение пришло из Telegram и
обрабатывает его внешняя модель, нужны оба. Без этих переключателей заметка наружу не уходит, какой бы адрес ни
был вписан.

**Telegram и модель.** Бот может работать с любой моделью; по умолчанию — со своей, локальной (владелец: «лучше
только с локальной, хотя это выбор человека»). Внешняя модель для бота включается отдельным переключателем с
предупреждением.

**Бот — часть Notio, MCP ему не нужен.** Бот работает внутри Notio на компьютере и вызывает команды напрямую. MCP —
это вход для *чужих* программ (LM Studio и других). Связка «Telegram ↔ Notio» строится без MCP.

### Сравнение

| | А. Чат в Notio | Б. MCP | В. Telegram |
| --- | --- | --- | --- |
| Где пишете | В окне Notio | В LM Studio или другой программе | В Telegram на телефоне |
| Заметки покидают компьютер | Нет | Нет | Да, через Telegram |
| Что открывается наружу | Ничего | Вход на этом компьютере, с ключом | Бот в интернете |
| Сложность | Меньше всего | Средняя | Больше всего |
| Облачная пауза (правило 10) | Не касается | Не касается | Нужно снять |

## 7. Журнал с откатом (слой 4)

Сейчас в Notio есть журнал бюджета и корзина, общего журнала нет — его надо построить.

```
 поручение «разложи заметки по папкам»
        │
        ▼
 ┌─ запись журнала № 17 ─────────────────────────────────────────────┐
 │ когда: 13.10 21:40     откуда: чат     слова: «разложи заметки…»  │
 │                                                                   │
 │ как было (снимок до изменений)        что сделано                 │
 │  • «Счёт за свет» — папка Дом          → перемещена в Платежи     │
 │  • «Отчёт» — папка Дом                 → перемещена в Работа      │
 │  • (папки «Платежи» не было)           → создана папка Платежи    │
 │                                                                   │
 │                                              [ Откатить ]         │
 └───────────────────────────────────────────────────────────────────┘
        │  нажали «Откатить»
        ▼
 заметки возвращаются в прежние папки с прежним текстом;
 созданное помощником уходит в корзину (не удаляется совсем)
```

Правила журнала:

- **Одно поручение — одна запись**, сколько бы команд в нём ни было. Откатывается целиком.
- **Снимок делается до первого изменения** и только для того, что затронуто. Чтение в журнал не пишет снимков.
- **Откат ничего не уничтожает:** созданное уходит в корзину.
- **Если после помощника заметку правили вы** — откат сначала спрашивает, а не затирает молча вашу правку.
- **Где хранится:** отдельный файл на устройстве, не новая таблица базы. Тогда схема базы, резервная копия и
  синхронизация не меняются (правило 8). Записи старше выбранного срока удаляются сами.
- Первый набор команд не трогает файлы фото, видео и звука — у них тяжёлые снимки. Для них остаётся корзина.

## 8. Личные заметки: «не для помощника»

Мысль владельца (2026-10-13): у заметки есть отметка — если она стоит, помощник эту заметку не обрабатывает, ни
через чат, ни через MCP, ни через Telegram. Что-то личное остаётся только вашим, остальное — обычное, им можно
управлять словами. В настройках выбирается, с какой отметкой создаётся новая заметка.

Отметка проверяется **в одном месте — в слое команд**. Поэтому она действует одинаково на все три входа, и её нельзя
обойти, придя с другой стороны.

```
                         ┌───────────────── слой команд ─────────────────┐
  чат в Notio ──┐        │                                               │
                │        │   «Помощник» у заметки выключен?              │
  MCP ──────────┼──────► │      да  ─► её как будто нет: не в списках,   │ ──► обычные заметки
                │        │            не в поиске, не читается,          │     идут дальше:
  Telegram ─────┘        │            не меняется                        │     журнал ─► действия
                         │      нет ─► команда выполняется               │
                         └───────────────────────────────────────────────┘
```

### Принято владельцем (2026-10-13)

1. **Доступ помощника — это переключатель и два уточнения под ним**, у заметки и у папки (владелец, 2026-10-13:
   «не надо чётко выбирать уровень: помощник включён — и уже тогда выбор, Telegram да или нет, внешние сервисы
   или локальные»; «сложнее, но и надёжнее»):

   ```
    Доступ помощника
    [●] Помощник                        ◄─ главный: выключен — заметки для помощника нет нигде
        [ ] Можно в Telegram            ◄─ показывать и менять заметку из Telegram
        [ ] Можно внешней модели        ◄─ отдавать текст заметки внешнему сервису
    [ ] Напоминания в Telegram          ◄─ отдельно: работает и при выключенном помощнике (раздел 6)
   ```

   Два уточнения видны, только когда «Помощник» включён, и только если Telegram или внешняя модель вообще
   настроены. Что из этого получается:

   | Помощник | Можно в Telegram | Можно внешней модели | Кто видит заметку |
   | --- | --- | --- | --- |
   | выкл | — | — | Никто |
   | вкл | нет | нет | Своя модель, чат в Notio и MCP на компьютере |
   | вкл | да | нет | Ещё и Telegram, но только когда бот работает со своей моделью |
   | вкл | нет | да | Ещё и внешняя модель, но только из чата в Notio |
   | вкл | да | да | Все входы и любая модель |

   Своя модель на этом компьютере или в домашней сети доступна всегда, когда «Помощник» включён: текст не покидает
   ваших устройств. Поручение из Telegram, которое обрабатывает внешняя модель, требует **обоих** уточнений.

   Раньше в этом плане стояли три уровня («Только я», «Помощник», «Помощник и внешние сервисы»); владелец заменил
   их переключателями. Там, где ниже осталось слово «уровень» или «доступ», оно значит этот набор переключателей.

2. **По умолчанию «Помощник» выключен.** Новая заметка закрыта от помощника, пока вы сами не откроете её. В
   настройках это можно поменять — для тех, кому удобнее наоборот.
3. **Переключатели папки — это то, с чем в ней создаются заметки.** Создали заметку в папке «Работа», у которой
   «Помощник» включён, — у заметки он тоже включён. Если у папки ничего не задано — действует общая настройка из
   пункта 2.
4. **При обновлении всё закрыто.** Миграция выключает «Помощника» у всех существующих заметок и папок. Помощник в первый
   день не видит ничего.
5. **Открыть разом: кнопка в папке.** В папке ставите переключатели и нажимаете «Применить ко всем заметкам» — их
   получают все заметки папки, и они же остаются у папки для новых. Перед применением Notio говорит, сколько
   заметок изменится. Той же кнопкой всем заметкам папки ставится и переключатель «Напоминания в Telegram»
   (раздел 6, вариант В).
6. **Отметка не действует назад** — принято как есть: что модель уже прочитала, то прочитала.

```
 папка «Работа»   [●] Помощник  [ ] Telegram  [ ] Внешняя модель      [ Применить ко всем заметкам ]
 ├─ Отчёт            помощник включён      ◄─ получила от кнопки
 ├─ Пароли от VPN    помощник выключен     ◄─ вы потом закрыли её отдельно
 └─ (новая заметка)  помощник включён      ◄─ берёт переключатели папки при создании
```

Как это задумано:

| Вопрос | Предложение |
| --- | --- |
| Что видит модель у заметки, закрытой для этого входа | Ничего: ни названия, ни текста, ни того, что заметка есть |
| Что будет при «перемести все заметки папки» | Закрытые остаются на месте; помощник отвечает «3 заметки пропущены» — число, без названий |
| Кто меняет уровень | Только вы, нажатием в заметке или в папке. Команды для этого в меню помощника нет — иначе модель открыла бы себе доступ сама |
| Новая заметка | Переключатели папки, а если у папки ничего не задано — общая настройка (по умолчанию «Помощник» выключен) |
| Заметка, созданная самим помощником | Исключение из правила «по умолчанию выключен»: у неё включено то, через что она создана (из чата на компьютере — «Помощник»; из Telegram — ещё и «Можно в Telegram»; внешней моделью — ещё и «Можно внешней модели»), иначе помощник не увидит то, что сам создал. В папку с выключенным «Помощником» он создавать не может |
| Где хранится уровень | В самой заметке и в папке, как «Скрыть содержимое» (D363): поле в базе, в копии и в синхронизации |
| Скрытая заметка (D363) и личная | Разные вещи: «скрыть» — от взгляда на экран, «личная» — от модели. Ставятся в одном месте, рядом |

### Критика: что в этой мысли хорошо и где она недотягивает

Мысль правильная и сильнее, чем «скрыть содержимое»: защита стоит не на экране, а на единственной двери, через
которую модель вообще получает данные. Но есть шесть мест, где простая галка на заметке работает хуже, чем кажется.
Пункты 1–4 владелец принял — они стали решениями выше. Пункт 5 — не выбор, а свойство синхронизации: о нём пишется
в справке. По пункту 6 принято (владелец, 2026-10-13): метки заметки и её место в числах отдаются помощнику только тогда,
когда ему открыта сама заметка; увидеть и изменить напоминания заметки помощник тоже может только у открытой ему
заметки. Пересылка напоминаний в Telegram — отдельный переключатель на заметке (раздел 6).

1. **Галка на каждой заметке — это много нажатий, и про неё забывают.** Личное обычно лежит рядом: папка «Финансы»,
   папка «Здоровье». Надёжнее отметка **на папке**: всё, что в ней есть и что в неё попадёт, личное. Галка на
   отдельной заметке остаётся — для одной личной заметки в обычной папке.
2. **Что делать с заметками, которые уже есть.** В день, когда помощник появится, у всех заметок отметки нет. Если
   считать это «обычная» — модель сразу видит всё, включая личное, которое вы не успели отметить. Безопаснее
   наоборот: **сначала помощнику не видно ничего**, и вы открываете ему папки по одной. Это та же настройка «по
   умолчанию», но применённая и к старым заметкам.
3. **Одной галки мало для Telegram.** Локальный чат и Telegram — разный риск: в первом случае текст не покидает
   компьютер, во втором идёт через чужие серверы. «Обычную» рабочую заметку можно отдать локальной модели и при этом
   не хотеть видеть её в Telegram. Предложение — не «да / нет», а три ступени:

   | Ступень | Чат в Notio и MCP на компьютере | Telegram |
   | --- | --- | --- |
   | Личная | Нет | Нет |
   | Только на компьютере | Да | Нет |
   | Везде | Да | Да |

   Владелец пошёл дальше ступеней: отдельные переключатели для Telegram и для внешней модели (см. «Принято»).
4. **Отметка не действует назад.** Если модель уже прочитала заметку, а вы потом сделали её личной, текст остался в
   истории чата, в журналах LM Studio и в переписке Telegram. Notio этого стереть не может. Правило простое:
   личное отмечается **до** того, как помощник включён, отсюда и пункт 2.
5. **Отметка должна доехать до компьютера.** Помощник работает на компьютере, а заметку вы можете сделать личной на
   телефоне. Пока не прошла синхронизация, на компьютере она ещё обычная. Значит, отметка обязана входить в
   синхронизацию, а новая заметка с телефона — приходить уже с отметкой по настройке телефона.
6. **Косвенные следы остаются.** Модель не видит личную заметку, но может заметить, что в папке «12 заметок», а
   показано 9; видит метку, которая стоит только на личных заметках; видит напоминание, привязанное к личной
   заметке. Полностью закрыть это нельзя; разумная граница — личные заметки не входят в счётчики и списки, которые
   отдаются модели, а их напоминания и метки ей не называются.

Чего отметка **не делает**, и это надо написать в справке прямо: она не шифрует заметку и не прячет её от человека с
открытым приложением. Это запрет для помощника, а не замок. Замок — блокировка приложения и шифрование базы.

Цена для разработки: ещё одно поле у заметки и у папки — следующий шаг схемы базы, с миграцией на обеих платформах,
как у «Скрыть содержимое». Делается на этапе 1, вместе со слоем команд: без отметки слой команд выпускать нельзя.

## 9. Права помощника: что ему вообще разрешено

Мысль владельца (2026-10-13): помощник может управлять всем — заметками, оформлением, настройками, — но что именно
ему можно, задаётся в приложении **по пунктам**. По умолчанию всё выключено; есть «Включить все» и «Выключить все».

Это вторая проверка в слое команд, рядом с уровнем доступа заметки. Они отвечают на разные вопросы:

```
  команда от модели: «переименуй заметку Отчёт»
            │
            ▼
   ┌──────────────────────────────┐  нет ─► «Это действие помощнику не разрешено»
   │ 1. ПРАВО: можно ли помощнику │
   │    менять заметки вообще?    │
   └──────────────────────────────┘
            │ да
            ▼
   ┌──────────────────────────────┐  нет ─► заметки для помощника как будто нет
   │ 2. УРОВЕНЬ: открыта ли ему   │
   │    именно эта заметка?       │
   └──────────────────────────────┘
            │ да
            ▼
        журнал ─► действие
```

Право — про **действие** («можно ли менять заметки»). Уровень из раздела 8 — про **заметку** («можно ли трогать эту»).

### Экран «Права помощника»

```
 Настройки → Помощник → Права

 [ Включить все ]   [ Выключить все ]

 Заметки
   ☐ Читать: списки, поиск, текст
   ☐ Создавать заметки
   ☐ Менять текст и название
   ☐ Перемещать и сортировать
   ☐ Метки, цвет, закрепление
   ☐ Отправлять в корзину
 Содержимое
   ☐ Списки: пункты и отметки
   ☐ Задачи: статус и сроки
   ☐ Бюджет: суммы
   ☐ Напоминания: создавать и менять
 Папки
   ☐ Создавать, переименовывать, порядок
 Приложение
   ☐ Экран: открывать папки и заметки
   ☐ Оформление: тема, цвета, шрифт, фон
   ☐ Настройки приложения

 Никогда, этого в списке нет:
   права помощника · уровни доступа заметок · блокировка и пароли ·
   шифрование · сопряжение устройств · очистка корзины ·
   настройки корзины и резервных копий
```

- **По умолчанию всё выключено.** Включили помощника — он не умеет ничего, пока вы не отметите пункты.
- **«Включить все»** отмечает все пункты списка и перед этим спрашивает один раз, перечислив, что откроется.
  Того, что в блоке «Никогда», оно не касается (владелец, 2026-10-13: «никогда»).
- **«Выключить все»** снимает всё сразу, без вопроса: это всегда безопасно.
- **Изменение действует сразу**, в том числе на поручение, которое выполняется прямо сейчас.
- **Изменение настроек помощником тоже пишется в журнал** (раздел 7) и откатывается: тема, шрифт и остальное
  возвращаются как были.
- Права хранятся на устройстве, в копию и в синхронизацию не входят: помощник на этом компьютере — права этого
  компьютера.

### Критика

1. **Права самого помощника помощнику давать нельзя.** В вашем списке был пункт «может ли менять настройки прав».
   Если такой пункт включить, все остальные галки перестают что-либо значить: модель, которой запретили удалять,
   сама себе разрешит и удалит. То же с уровнями доступа заметок: открывать себе закрытые заметки помощник не должен
   уметь ни при каких правах. Поэтому эти два пункта стоят в блоке «Никогда», и «Включить все» их не включает.
   Менять права может только человек, нажатием в приложении.
2. **Блокировка, пароли, шифрование — тоже «Никогда».** Ошибка модели здесь не откатывается журналом: выключенная
   блокировка или сменённый пароль — это уже не «вернуть как было», а потерянная защита или потерянный доступ.
3. **Для Telegram нужен свой, более узкий набор.** Локальный чат и MCP работают на вашем компьютере, а в Telegram
   пишут из интернета. Разумно иметь два столбца галок: «на этом компьютере» и «из Telegram», и второй по умолчанию
   пуст даже после «Включить все». Пока Telegram не делается, столбец один.
4. **Пунктов не должно быть много.** Четырнадцать галок — граница, после которой их перестают читать и жмут
   «Включить все». Поэтому права идут по смысловым группам, а не по одной на каждую команду.
5. **«Читать» — отдельная и первая галка.** Без неё помощник бесполезен, а с ней одной он уже может отвечать на
   вопросы и искать, ничего не меняя. Это и есть режим «только читает», отдельный переключатель для него не нужен.
6. **«Настройки приложения» — широкий пункт.** Туда попадает и срок хранения корзины. Если помощник поставит
   «очищать корзину через 1 день», это косвенное удаление. Принято (владелец, 2026-10-13): настройки корзины и
   резервных копий в этот пункт не входят, их меняет только человек.

## 10. Как это настраивается

Всё лежит в одном месте: **Настройки → Помощник**. Четыре страницы — подключение, права, доступ к заметкам, журнал.
Пока главный переключатель выключен, помощника в приложении нет вообще.

```
 Настройки → Помощник

 Помощник                                   [ выключен ◯ ]   ◄─ главный переключатель
 ─────────────────────────────────────────────────────────
 Подключение       модель не выбрана                    ›
 Права             ничего не разрешено                  ›
 Доступ к заметкам помощник выключен у всех заметок     ›
 Журнал            пусто                                ›
```

### Где что работает: помощник живёт на компьютере

**Схема, из которой исходим (владелец, 2026-10-13):**

```
 ┌──────────── компьютер: Windows или Linux ────────────┐                  ┌──── телефон: Android ────┐
 │                                                      │                  │                          │
 │  LM Studio ◄──► Notio ◄──► бот Telegram ─────────────┼──► Telegram ───► │  приложение Telegram     │
 │   модель         команды     (внутри Notio)          │    (интернет)    │   чат с ботом            │
 │                  права                               │                  │                          │
 │                  журнал                              │   VPN до дома    │  Notio для Android       │
 │                  заметки ◄───────────────────────────┼──────────────────┼─► обычная синхронизация  │
 └──────────────────────────────────────────────────────┘                  └──────────────────────────┘
```

Две дороги между компьютером и телефоном, у каждой своё дело: **Telegram — для слов** (поручения и ответы),
**VPN — для данных** (синхронизация заметок). Модель и все настройки помощника — только на компьютере.

Принято владельцем (2026-10-13): помощник настраивается и работает **в Notio для Windows и Linux**. Там же
запускается бот. Телефон с Android на первых этапах в этом не участвует: он получает то, что помощник изменил,
обычной синхронизацией, как любое другое изменение, сделанное на компьютере.

Позже (владелец, тот же день): у Android может появиться **свой чат** — телефон подключается к модели сам, к
внешнему сервису или к LM Studio в домашней сети, и поручения выполняются прямо на телефоне. Это отдельный
этап 6 (раздел 12): на телефоне придётся построить те же слои — команды, права, журнал с откатом.

```
 ┌──────────────── компьютер (Windows или Linux) ────────────────┐          ┌──── телефон (Android) ────┐
 │                                                               │          │                           │
 │   LM Studio ◄──► Notio                                        │          │   Notio                   │
 │    модель         ├─ настройки помощника                      │  обычная │    заметки                │
 │                   ├─ права и уровни                           │ синхро-  │    те же поля у заметок:  │
 │   бот Telegram ──►├─ команды                                  │ низация  │    уровень, напоминания   │
 │   (если включён)  ├─ журнал с откатом                         │ ◄──────► │                           │
 │                   └─ заметки                                  │          │   помощника здесь нет     │
 └───────────────────────────────────────────────────────────────┘          └───────────────────────────┘
```

Что из этого следует:

- **До этапа 6 на телефоне нет ни настроек помощника, ни чата, ни журнала.** Права и журнал хранятся на компьютере.
- **Поля заметки на телефоне всё равно нужны.** Уровень доступа и переключатель напоминаний лежат в самой заметке,
  значит, Android должен их хранить и не терять при синхронизации; иначе заметка, пройдя через телефон, вернётся
  без уровня. Это шаг схемы базы на обеих платформах.
- **Заметка, созданная на телефоне,** приходит на компьютер с выключенным «Помощником» — помощник её не видит, пока вы не
  откроете её на компьютере. Показывать и менять уровень на самом телефоне — отдельный вопрос, не для первой версии.
- **До этапа 6 управлять с телефона можно только через Telegram** (вариант В): бот работает на компьютере, телефон
  — просто окно, в которое вы пишете.

**Открытый вопрос (владелец: «надо думать»): как быстрее доносить изменения до телефона.** Сейчас телефон узнаёт о
работе помощника только при очередной синхронизации. Что можно сделать, не решая сейчас:

| Способ | Когда работает | Цена |
| --- | --- | --- |
| Компьютер сам запускает синхронизацию после поручения помощника | Телефон дома, в той же сети, и у него включено «Всегда готов к синхронизации» | Почти ничего: всё уже есть, нужен только запуск |
| Бот присылает в Telegram текст того, что изменилось | Везде, где есть интернет | Текст идёт через Telegram; это копия для чтения, а не заметка в Notio на телефоне |
| Облачная синхронизация | Везде | Облачные сервисы на паузе (правило 10); большая отдельная работа |

### Telegram как мост между компьютером и телефоном

Вопрос владельца (2026-10-13): «LM Studio + бот + Notio на компьютере ↔ бот + Notio на Android — реально? И
синхронизацию через него же?» Ответ по частям; сведения о Telegram записаны по памяти и проверяются до кода.

```
  компьютер                              Telegram                         телефон

 LM Studio ─ Notio ─ бот  ◄──────────►  серверы  ◄──────────►  приложение Telegram   ✔ работает: вы пишете боту
                                                   ◄────✘────►  Notio для Android     ✘ напрямую нельзя
```

| Что хочется | Реально? | Почему |
| --- | --- | --- |
| Писать поручения с телефона в приложении Telegram | Да | Это вариант В, он уже в плане |
| Notio на телефоне сам переписывается с ботом компьютера | Напрямую нет | Бот слышит людей, а не программы: вторая программа с тем же ботом не получает его сообщений, а второй бот не слышит первого |
| То же через закрытый канал Telegram с двумя ботами | Возможно, **проверить** | Если бот получает записи канала, сделанные другим ботом, канал становится почтовым ящиком между компьютером и телефоном |
| То же, но Notio входит в Telegram как вы | Технически да, не советую | Notio получил бы полный доступ к вашему аккаунту Telegram; тяжёлая чужая библиотека; вход по номеру внутри Notio |
| Синхронизация руками: бот присылает файл, вы открываете его в Notio | Да, просто | Бот отправляет файл заметки или пакет изменений; на телефоне «Открыть в Notio». Обратно — «Поделиться» из Notio в чат бота |
| Синхронизация сама, без нажатий | Только если сработает канал с двумя ботами | И только пока Notio на телефоне открыт: фоновой работы на Android нет (правило 2, `docs/BATTERY_RU.md`) |

Если делать синхронизацию через Telegram, то только так: пакет шифруется на устройстве ключом сопряжения, который
у Notio уже есть для синхронизации по сети, и Telegram видит один шифр. Ограничения Telegram на размер файлов у ботов
(десятки мегабайт, проверить) значат: заметки и рисунки — да, видео — нет. И это облачная синхронизация под другим
именем: правило 10.

**Способ без единой строки кода** (на выбор владельца): частная сеть между своими устройствами (например,
Tailscale или свой WireGuard). Телефон тогда «дома» из любого места: обычная синхронизация Notio по сети и LM Studio
на компьютере доступны как по домашнему Wi-Fi. Синхронизация Notio такие адреса уже принимает (Android D231:
диапазон 100.64/10). Цена: ещё одна программа на телефоне и компьютере; у Tailscale — чужой сервис, который сводит
устройства друг с другом, сам трафик идёт между ними зашифрованным.

**Выбрано владельцем (2026-10-13): у него уже есть VPN до дома** — связь телефона с компьютером вне дома идёт через
него, Telegram для синхронизации не нужен и остаётся только чатом. Проверить на его сети до того, как на это
опираться: телефон по VPN получает адрес, который синхронизация Notio принимает как местный; поиск устройств через
VPN, скорее всего, не находит компьютер, и адрес надо вписать вручную (это уже есть: Android D280, D357).

### Шаг за шагом: чат в Notio (вариант А)

```
 1. В LM Studio       2. Подключение        3. Права            4. Заметки           5. Чат
 загрузить модель,    адрес, «Проверить»,   отметить, что       открыть папки,       значок чата,
 запустить сервер  ─► выбрать модель     ─► помощнику можно  ─► которыми можно    ─► писать поручение
                                                                 управлять
```

| Шаг | Где | Что делаете | Что видите |
| --- | --- | --- | --- |
| 1 | LM Studio (или внешний сервис) | Загружаете модель и запускаете её сервер; у внешнего сервиса берёте адрес и ключ | Адрес вида `http://localhost:1234/v1` (проверить на этапе 0) |
| 2 | Помощник → Подключение | Вписываете адрес и, если нужен, ключ; нажимаете «Проверить» | «Связь есть», подпись «Этот компьютер», «Домашняя сеть» или «Внешний сервис», список моделей; выбираете одну. Или понятная ошибка: «сервер не отвечает» |
| 3 | Помощник → Права | Отмечаете пункты; для начала — только «Читать» | Строка «Разрешено: чтение» |
| 4 | Помощник → Доступ к заметкам | У нужной папки включаете «Помощник» и нажимаете «Применить ко всем заметкам» | Список папок с переключателями; у каждой — сколько заметок открыто |
| 5 | Верх окна, значок чата | Пишете поручение | Ответ; если что-то менялось — «Изменено 3 заметки · Откатить» |

Шаг 4 можно делать и с другой стороны: в самой папке и в самой заметке, в их меню — «Доступ помощника». Страница в
настройках нужна, чтобы видеть всё разом.

```
 Помощник → Доступ к заметкам

 Новые заметки по умолчанию:   [ ] Помощник

 Папка       Помощник   Telegram   Внешняя модель   Открыто помощнику
 Работа        [●]        [ ]          [ ]           14 из 15     [ Применить ко всем ]
 Дом           [ ]         —            —             0 из 22     [ Применить ко всем ]
 Финансы       [ ]         —            —             0 из 8      [ Применить ко всем ]
```

### Если нужен MCP (вариант Б)

| --- | --- | --- |
| 1 | Помощник → Подключение → «Другие программы (MCP)» | Включаете. Notio показывает готовый блок настроек с адресом и ключом и кнопку «Копировать» |
| 2 | LM Studio, настройки MCP | Вставляете блок (как именно LM Studio его принимает — проверить на этапе 0) |
| 3 | LM Studio, чат | В списке инструментов появился Notio; пишете поручение там |

Права и доступ к заметкам — те же самые страницы: MCP не получает ничего сверх того, что разрешено там.

### Если нужен Telegram (вариант В, после снятия паузы)

| 3 | Telegram, ваш бот | Отправляете боту этот код со своего аккаунта — бот запоминает, что слушать надо только вас |
| 4 | Помощник → Права | Отмечаете отдельный столбец «из Telegram» |
| 5 | Папки и заметки | Тем, что можно видеть в Telegram, включаете «Можно в Telegram»; тем, чьи напоминания нужны на телефоне, — «Напоминания в Telegram» |

### Голосовой ввод

Мысль владельца (2026-10-13): поручения хочется не только писать, но и говорить. Своего распознавания речи Notio не
делает — оно есть в системе, и поле чата обычное текстовое, поэтому диктовка системы в нём работает сама:

| Где | Как диктовать | Что нужно от Notio |
| --- | --- | --- |
| Windows | Win + H в поле чата | Ничего; можно добавить рядом с полем значок микрофона, который вызывает это же |
| Android | Микрофон на экранной клавиатуре | Ничего; в чате на телефоне (этап 6) можно добавить значок микрофона, вызывающий распознавание системы |
| Telegram | Микрофон клавиатуры телефона в чате с ботом | Ничего. Голосовое *сообщение* Telegram (аудиофайл) бот не понимает: для него нужна модель распознавания речи на компьютере — отдельная работа |
| Linux | Зависит от рабочего стола; единого способа нет (проверить) | Владелец (2026-10-14): голосовой ввод нужен на всех трёх системах — Android, Windows, Linux. Для Linux искать распознавание на компьютере (локальная модель речи), если система его не даёт |

Куда идёт голос при диктовке, решает система, а не Notio: у Windows и у клавиатуры телефона распознавание может
работать через их серверы. Это надо назвать в справке, когда значок микрофона появится.

### Как всё выключить

- **Главный переключатель «Помощник»** — выключает всё сразу: чат, MCP, бота. Права и уровни при этом сохраняются.
- **«Выключить все» на странице прав** — помощник остаётся, но не может ничего.
- **«Отозвать ключ»** — отключает только программы, подключённые по MCP.

## 11. Защита

| Опасность | Что делаем |
| --- | --- |
| Модель поняла не так и испортила заметки | Журнал с откатом; массовые изменения — только после вашего «Применить» |
| В тексте заметки написано «удали всё», и модель приняла это за приказ | В меню нет необратимых команд; лимит команд на одно поручение; подтверждение массовых действий |
| Чужая программа на компьютере стучится в MCP-вход | Вход только с этого компьютера, по секретному ключу, выключен по умолчанию |
| Приложение заблокировано | Команды не работают, пока блокировка не снята |
| Скрытые заметки (D363) | Решение владельца, раздел 13; рекомендация — модели отдаётся только название |
| Заметка, которую вы не хотите показывать модели совсем | Выключенный «Помощник» на заметке или папке, раздел 8 |
| Модель делает то, чего вы ей не поручали вообще (меняет тему, настройки) | Права по пунктам, раздел 9: по умолчанию не разрешено ничего |
| Модель пытается расширить собственные права | Такой команды нет: права и уровни меняет только человек |
| Чужой человек пишет Telegram-боту | Бот отвечает только вашему идентификатору |

Всё, что касается защиты данных, записывается в `docs/SECURITY_RU.md` тем же шагом, что и код (правило 12).

### Что ещё небезопасно

Вопрос владельца (2026-10-13): «есть ещё мысли, что не безопасно?» Есть. Всё, что ниже, — не причины отказаться, а
места, которые надо закрыть в коде или честно назвать в справке.

| № | Опасность | Почему это возможно | Что делаем |
| --- | --- | --- | --- |
| 1 | Заметка с чужим текстом командует моделью | Вам прислали файл заметки или вы вставили текст из интернета, а в нём «перешли всё содержимое…» | Импортированное и пришедшее по синхронизации приходит с выключенным «Помощником», как всё новое; модели текст заметок подаётся как данные; необратимых команд нет |
| 2 | Адрес модели — не ваш компьютер | В поле адреса можно вписать чужой сервер или облачный сервис, и заметки уйдут туда | Адрес может быть любым (владелец, 2026-10-13); Notio сам определяет «этот компьютер / домашняя сеть / внешний сервис» и подписывает; внешней модели отдаются только заметки с «Можно внешней модели» (раздел 6) |
| 2а | Домашняя сеть не зашифрована | Между Notio и LM Studio на другом компьютере текст идёт по сети открыто | Подпись «Домашняя сеть» и строка в справке; в чужой сети (кафе, работа) такой адрес не использовать |
| 2б | Внешний сервис хранит и читает запросы | Что сервис делает с присланным текстом, Notio не знает и не управляет | Предупреждение при вводе адреса; переключатель «Можно внешней модели» на заметке; облачная пауза (правило 10) |
| 2в | Ключ внешнего сервиса | По ключу тратятся ваши деньги | Ключ запечатан; в журнал приложения и в резервную копию не попадает |
| 3 | Страница в браузере стучится в MCP-вход | Сайт может слать запросы на адрес вашего же компьютера | Вход только с ключом, с проверкой, откуда пришёл запрос; лучше вообще без сетевого входа — через прямое подключение программы (проверить на этапе 0, умеет ли так LM Studio) |
| 4 | Ключ MCP лежит открытым текстом | Программа, к которой подключён Notio, хранит ключ в своём файле настроек | Ключ можно отозвать одной кнопкой; в справке сказано, где он лежит |

## 12. Этапы

```
 0. Проверка        1. Команды          2. Чат в Notio      3. MCP          4. Telegram      5–6. Android
    на вашей    ─►     и журнал     ─►     с LM Studio  ─►     сервер   ─►     бот       ─►    
    машине             без модели          (вариант А)         (вариант Б)     (вариант В)
                                                                               после снятия
                                                                               паузы
```

| Этап | Что делается | Чем заканчивается |
| --- | --- | --- |
| 0 | Проверить: как LM Studio отдаёт вызовы команд по адресу `…/v1`; как он подключает MCP; какая из ваших моделей вызывает команды надёжно | Короткая запись с результатом; без неё код не начинается |
| 1 | Слой команд, доступ помощника у заметки и папки и журнал с откатом на Windows и Linux, без модели | Тесты: каждая команда выполняется и откатывается; личная заметка не видна ни одной команде |
| 2 | Чат в Notio: адрес и модель в настройках, выключено по умолчанию; сначала только чтение, затем изменения | Можно дать поручение в окне Notio и откатить его |
| 3 | MCP-сервер с ключом | Те же команды доступны из LM Studio |
| 4 | Telegram-бот | Только после решения по паузе |
| 5 | Android: поля заметки (уровень, напоминания в Telegram) хранятся и синхронизируются; помощника на телефоне ещё нет (раздел 10) | Заметка проходит через телефон и не теряет уровень |
| 6 | Android: свой чат в Notio на телефоне с моделью по адресу (внешний сервис или LM Studio в домашней сети); команды, права и журнал с откатом на телефоне. Без MCP и без бота: правила фона и батареи (`docs/BATTERY_RU.md`) | Поручение выполняется на телефоне и откатывается там же |

Этап 1 — самый большой и нужен при любом варианте входа.

## 13. Что решает владелец

1. **Первый вход после этапа 1:** чат в Notio (рекомендация: он проще и ничего не открывает наружу) или MCP.
2. **Подтверждение:** перед каждым изменением или только перед массовыми (рекомендация: только перед массовыми —
   откат есть на всё).
3. **Telegram:** принято 2026-10-14 — владелец попросил сделать встроенного бота; пауза на облачные сервисы снята для
   этого бота и ни для чего больше. Внешняя модель остаётся под паузой.
4. **Скрытые заметки:** отдавать ли модели их содержимое (рекомендация: нет, только название).
5. **Срок хранения журнала помощника:** например, 30 дней или последние 200 записей.
6. **Доступ помощника к заметкам, раздел 8.** Принято 2026-10-13: переключатель «Помощник» на заметке и на папке и
   под ним два уточнения — «Можно в Telegram» и «Можно внешней модели»; отдельно «Напоминания в Telegram»; по
   умолчанию всё выключено, меняется в настройках; при обновлении всё закрыто; кнопка «Применить ко всем заметкам»
   в папке. Режима «помощник читает, но не меняет» у заметки нет: то же даёт одно право «Читать» из раздела 9.
   Метки и место в числах идут за доступом своей заметки.
7. **Права помощника, раздел 9.** Принято 2026-10-13: права по пунктам, по умолчанию всё выключено, кнопки
   «Включить все» и «Выключить все»; права помощника, уровни заметок, блокировка, пароли и шифрование не даются
   ему **никогда**; настройки корзины и резервных копий меняет только человек. Остаётся решить:
   - отдельный набор прав для Telegram (рекомендация: да, когда дойдёт до Telegram).
8. **Модель.** Принято 2026-10-13: адрес любой — этот компьютер, домашняя сеть или внешний сервис, с ключом или
   без; для бота по умолчанию своя модель, внешняя — по выбору человека. Остаётся решить:
   - внешний сервис — это облачный сервис: снимается ли для него пауза правила 10 (без этого внешняя модель в
     плане есть, а в код не идёт). Пауза — правило самого владельца от 2026-09-24: «облачные системы пока не
     трогаем, отложено, на паузе»; под неё попадает всё, что отправляет заметки на чужие серверы, — и внешняя
     модель, и Telegram.
9. **Блокировка и бот.** Принято 2026-10-13: пока Notio на компьютере заблокирован, Telegram-бот не отвечает.
   В настройках бота есть переключатель «Отвечать, когда Notio заблокирован», по умолчанию выключен: выбор за
   человеком. При включении Notio предупреждает, что блокировка перестаёт защищать то, что открыто боту.
10. **Где работает помощник.** Принято 2026-10-13: сначала только Windows и Linux, бот запускается там же; Android
    получает изменения синхронизацией, а свой чат на телефоне — этап 6. Остаётся думать: как доносить изменения до
    телефона быстрее (раздел 10).

## 14. Чего ждать честно

- **Качество зависит от модели.** Небольшие локальные модели вызывают команды ненадёжно: путают параметры, делают
  лишнее. Поэтому откат и подтверждение — не дополнение, а обязательная часть.
- **Вся база в модель не помещается.** Команды отдают заметки порциями и через поиск; на «систематизируй тысячу
  заметок» модель будет работать долго и по частям.
- **Это не замена интерфейсу.** Нажать «сортировать» быстрее, чем написать об этом. Польза — в поручениях из многих
  шагов и в управлении с телефона.

## 15. Слова

| Слово | Что значит здесь |
| --- | --- |
| Модель | Программа, которая понимает текст и отвечает на него; у вас запущена в LM Studio |
| LM Studio | Программа на компьютере, которая запускает модель и отвечает на запросы по адресу вида `…/v1` |
| API | Способ, которым одна программа просит другую что-то сделать |
| Команда (инструмент) | Одно действие Notio с названием и параметрами, которое модели разрешено попросить |
| MCP | Общий язык, на котором программа с моделью узнаёт у другой программы список её команд и вызывает их |
| MCP-сервер | Программа, которая отдаёт свои команды по MCP; в варианте Б это Notio |
| Точка отката | Снимок «как было» перед поручением, из которого журнал всё возвращает |
| Личная заметка | Заметка или папка с отметкой, которую помощник не видит и не меняет ни через один вход |
| Право помощника | Разрешение на вид действий («менять заметки», «менять оформление»); задаётся в настройках по пунктам |

**Отличие от плана, сделанное намеренно.** В плане доступ помощника — поле самой заметки (шаг схемы базы на обеих
платформах). На ветке доступ и журнал лежат в двух отдельных таблицах рядом с заметками, а версия схемы не меняется.
Так база остаётся совместимой с `main`: поставили сборку с ветки, не понравилось — поставили обычную, и она откроет
ту же базу. Цена: доступ не уезжает на телефон при синхронизации. Пока помощник живёт только на компьютере, это не
мешает; при слиянии ветки в `main` доступ переедет в поле заметки, как в плане.
